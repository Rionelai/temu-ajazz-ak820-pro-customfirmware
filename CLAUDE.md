# CLAUDE.md - project memory (read this first)

Reviving a bricked **AJAZZ AK820 PRO** (Temu, box batch `980879`, PCB `SG-8975US-ARGB-1K`
`SG-00721 Ver:02`, dated 2026/08/24) with our own firmware, and preparing a public GitHub repo so
other owners of this board can fix theirs. The user is hands-on (solders, RGH3 experience), works
on Windows (PowerShell), and prefers short, plain instructions with exact steps.

Full hardware notes: [docs/HARDWARE.md](docs/HARDWARE.md). Recovery guide: [docs/RECOVERY.md](docs/RECOVERY.md).

## What happened / what we know (verified on the board)

- Brick cause: the official **2.4G upgrade tool** (`HFD_IAPTool`, contains only the *dongle*
  firmware) was run with the keyboard on USB -> dongle firmware written onto the keyboard.
- **U7 `HFDCKD101` = WCH CH584M** (QFN48, chip id 0x8416, 448K flash, **96K RAM**, ROM bootloader
  V2.30, factory config: boot enabled, debug off, read-out protected). Main MCU: matrix, knob, USB.
- **U8 `HFD8K1000` = WCH CH32V006** (QingKe V2C, 62K flash, read-protected). Talks to U7 via
  `TX1`/`RX1`. Reachable with a Pi Pico as WCH single-wire debugger (research/u8-probe).
- **Factory solder bridge** between U7 pins 25 (PB23) and 26 (PB22) blocked the ROM bootloader;
  removed with flux + wick. Needle on **pin 26 (PB22) to GND while plugging in** = ROM bootloader
  (USB 1A86:55E0), flash with **wchisp nightly** + WCH CH372DRV driver (CH375DLL64.dll).
- Key matrix: rows **PA10..PA15**, columns L->R **PA7 PA8 PA9 PB9 PB8 PB17 PB16 PB15 PB14 PB13
  PB12 PB7 PB6 PB5 PB4** (one diode per key, direction irrelevant to our scan). 82 keys incl.
  knob press. Mapping: `keymap.csv` (generated by tools/pairs_to_keymap.py from `pairs.csv`).
- **Knob encoder = PB0/PB1** (2 quadrature steps per detent, `KNOB_INVERT 1` on this board).
- PB20..PB23 toggle by themselves (likely the U8 link) - never used as key lines.
- USB = full-speed on PB10/PB11 (CH584 has no high-speed USB).

## Current firmware state (all working on the real keyboard)

- Flash layout: **IAP updater 0x0000-0x1FFF** (firmware/iap, WCH USB_IAP ported, USB 4348:55E0)
  + **app at 0x2000** (firmware/common/link_app.ld).
- **Updating WITHOUT opening the keyboard works**: `.\tools\update.ps1 [-Bin file.bin]`, then on
  the keyboard hold **Fn+Esc 3 s** (keyboard firmware) or **hold Esc while plugging in** (works
  from any firmware, IAP checks Esc = PA7/PA10 at boot). Needle trick only if the IAP itself breaks.
- `firmware/keyboard`: all 82 keys over USB HID (boot kb 6KRO, 1 kHz), knob = volume, knob press =
  mute, Fn layer (Fn+Backspace = Del, Fn+Delete = Insert, Fn+arrows etc. = lighting), Snap Tap compiled
  out (`ENABLE_SNAPTAP 0` - user wants it OFF; it is bannable in CS2).
- The keyboard runs the keyboard firmware again (2026-11-13).

## Build / flash commands

```
sh firmware/build.sh keyboard|keyfinder|ledfinder|iap|full   # uses .toolchain/ automatically
.\tools\update.ps1 -Bin .\firmware\out\<target>.bin          # normal way (no opening)
.\tools\flash_u7.ps1                                         # full.bin via ROM bootloader (needle)
.\tools\kf_serial.ps1                                        # log of finder firmwares (COM, 1209:0001)
python tools\gen_keymap.py                                   # keymap.csv -> firmware/keyboard/keymap.h
```
Local tools (gitignored): `.toolchain/xpack-riscv-none-elf-gcc-15.2.0-1`, `.toolchain/wchisp`
(nightly, with CH375DLL64.dll). WCH SDK is cloned to `firmware/sdk/ch585` (gitignored).
Gotchas: CH584 RAM is 96K (linker scripts patched); WCH's `mcpy` opcode replaced
(common/inc/core_riscv.h); interrupts built with `-DINT_SOFT` and HW stacking disabled in startup.

## Open work (next steps, in the user's priority order)

**User's plan (2026-11-13): three big items left, in this order: (1) 2.4G dongle, (2) settings

1. **RGB lighting - SOLVED (2026-11-13).** One addressable LED chain on **PA0** (CH584 "LED0" pin),
   idle low, byte order G,R,B, **Esc = LED 1, F1 = LED 2, then keys in order**. A buffer between
   PA0 and the LEDs stretches pulses, so WS2812 timing reads as all 1s (= all white, which is
   why phases 1-12 failed). Working timing: **0 = high 100 ns, 1 = high 1000 ns, 2.5 us/bit**,
   absolute SysTick deadlines, code in RAM (`firmware/keyboard/rgb.c`). Pulses >= ~200 ns read as
   1. Search history: firmware/ledfinder (phases 1-16; 13 = pulse count test, 14 = 0-shape test,
   16 = first correct colours). U8 is NOT involved in the LEDs.
   - keyboard firmware: white on boot VERIFIED on the board. Ajazz combos added (not verified yet):
     Fn+X on/off, Fn+\ effect (static/breathing/spectrum/wave), Fn+Right colour (8), Fn+Up/Down
     brightness (5, capped at 150/255 for USB power), Fn+Left direction, Fn+-/= speed. Settings
     saved in DataFlash block 1 (0x1000, 8 bytes: magic 0xA6 + on/mode/col/lvl/spd/dir + sum),
     written 1 s (SysTick) after the last combo, whole keyboard blinks 3x green (ok) / red (read-back failed). v1 at 0x100
     with a 256-byte erase did NOT save: the SDK's EEPROM_ERASE hangs (while(1)) on some variants
     unless the length is a multiple of 4096 -> always erase whole EEPROM_BLOCK_SIZE blocks
     (iap_flag.c fixed too). v2: save verified (green blink). The IAP never erases DataFlash. Fn+arrows no longer send PgUp/PgDn/Home/End (gen_keymap.py FN).
   - Lights go off while the USB bus is suspended (PC off/asleep with 5 V still on): rgb_task polls
     R8_USB_MIS_ST & RB_UMS_SUSPEND (255 passes ~300 ms to sleep, 5 to wake). On the user's PC
     Sleep did NOT turn them off: it uses Modern Standby (powercfg /a: S0 Low Power Idle, no S3),
     which keeps USB running. So also idle-off: lights off after 5 min without key/knob
     (IDLE_OFF_MS in rgb.c), first key brings them back. Shutdown not tested yet.
   - Chain = 85 LEDs: 0-81 keys, 82/83/84 = the indicators (phase 20 LED walk; which of the three
     verified on the board: 82 = W, 83 = C; battery icon is INSIDE 0-81 (it followed the effects; 81 VERIFIED: icon shows green while keys follow effects); 84 unknown). ADC (-12 dB raw): PA2 2212 rock steady
     (~1.39 V -> battery via assumed 1:3 = 4.16 V), PA1 ~2738 (~2.47 V = USB 5 V / 2?), PA3-5 drift.
     keyboard fw (not verified): C = Caps Lock from the host LED report (usb_hid.c host_leds),
     W = Fn+Win lock (drops 0xE3/0xE7, saved; settings magic 0xA7, 12 bytes), battery icon
     red/yellow/green (<3.6 / <3.9 / >=3.9 V) measured every 2 s. Effects run on keys only.
   - Exact chain order vs keymap (for per-key effects) still to map.
   - Still missing from the manual: Fn+Space (3-5 s) reset, Fn+1/2/3 game presets.
